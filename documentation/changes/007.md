## **2025-10-18 - Transition to Sprite-Based Tile Rendering**

### **Timestamp**: Saturday, October 18, 2025 (Late Evening)

### **Implemented By**: Jeremy Soo (with AI assistance)

### **Overview**

Transitioned from Graphics API to Sprite-based tile rendering for 100-300x performance improvement while maintaining the exact visual style of all tiles (grass dots, brick walls, grid floors, etc.).

---

## **1. Problem Statement**

### **Issue: Graphics API Performance Bottleneck**

**Current State**:

- Using Pixi.js Graphics API to render tiles
- Each tile drawn procedurally with patterns (dots, grids, bricks)
- Rendering ~1800 tiles takes 424ms
- Graphics API designed for dynamic drawing, not static content

**Documentation Reference** (from 004.md):

> "Graphics API is for dynamic, changing shapes. For static tile maps, Sprites are 100-300x faster because they use GPU batching."

**Performance Comparison** (from documentation):
| API | 1800 tiles | 4000 tiles | Notes |
|------------------|------------|--------------|------------------------------|
| **Graphics API** | 300-500ms | 600-1000ms | CPU-bound, unbatched |
| **Sprite API** | 1-3ms | 3-8ms | GPU-accelerated, batched |

**Improvement**: **100-300x faster** with sprites!

---

## **2. Solution: Texture Generation + Sprites**

### **Key Insight**

Keep the exact tile rendering code (patterns and all), but:

1. **Generate textures once** from the Graphics rendering
2. **Reuse textures** as Sprites for all tiles
3. **GPU batching** handles rendering automatically

This way we get:

- ✅ Same visual appearance (grass, walls, patterns preserved)
- ✅ 100-300x performance improvement
- ✅ No need for external image assets
- ✅ Textures generated from existing code

## **3. Implementation Details**

### **A. New File: `lib/textureGenerator.ts`**

**Purpose**: Convert Graphics rendering to reusable textures

**Key Functions**:

```typescript
// Generate a texture for a specific tile type
generateTileTexture(
  renderer: Renderer,
  tileType: TileType,
  tileSize: number,
  variant: number
): Texture

// Pre-generate all textures at startup
preGenerateAllTileTextures(
  renderer: Renderer,
  tileSize: number,
  maxVariants: number = 3
): void

// Get texture (generates if not cached)
getTileTexture(
  renderer: Renderer,
  tileType: TileType,
  tileSize: number,
  variant: number
): Texture
```

**How It Works**:

```
1. Create Graphics object
2. Call existing renderTile() function (preserves visual style)
3. Render Graphics to RenderTexture
4. Cache texture for reuse
5. Return texture

Result: Same appearance, but now as a reusable texture!
```

**Texture Cache**:

- Key format: `"tileType_variant"` (e.g., `"grass_0"`, `"wall_2"`)
- 7 tile types × 3 variants = 21 textures
- Pre-generated at startup for instant access

### **B. Updated: `lib/tileRenderer.ts`**

**New Function**: `renderTilesAsSprites()`

```typescript
export function renderTilesAsSprites(
  container: Container,
  renderer: Renderer,
  tiles: Tile[],
  tileSize: number
): void {
  // Clear existing sprites
  container.removeChildren();

  // Create a sprite for each tile
  for (const tile of tiles) {
    const texture = getTileTexture(
      renderer,
      tile.tileType,
      tileSize,
      tile.visualVariant || 0
    );

    const sprite = new Sprite(texture);
    sprite.x = tile.x * tileSize;
    sprite.y = tile.y * tileSize;

    container.addChild(sprite);
  }
}
```

**Old Function**: `renderTiles()` (Graphics API)

- Kept for reference but marked as legacy
- Replaced with Sprite version in actual usage

## **8. Technical Notes**

### **Texture Cache Strategy**

**Cache Key Format**: `"tileType_variant"`

**Example**:

```
grass_0 → Grass tile, variant 0
grass_1 → Grass tile, variant 1 (slightly different color)
wall_2 → Wall tile, variant 2
```

**Cache Size**:

- 7 tile types × 3 variants = 21 textures
- Each texture: 32×32 pixels @ 32-bit RGBA = 4KB
- Total memory: 21 × 4KB = ~84KB (minimal!)

**Cache Lifecycle**:

- Created once at map initialization
- Reused for all tiles of that type
- Cleared on component unmount (automatic cleanup)

### **Renderer Access Pattern**

**Challenge**: Hooks don't have direct access to Pixi renderer

**Solution**: Walk up the parent hierarchy

```typescript
const app = tilesLayer.parent?.parent?.parent;
const renderer = (app as any).renderer;
```

**Hierarchy**:

```
Application (has .renderer)
  └─ Stage (Container)
      └─ worldContainer (Container)
          └─ tilesLayer (Container) ← we start here
```

### **Type Safety**

**Convex Type Compatibility**:

- No changes needed for Sprite transition
- Tile data structure unchanged
- Only rendering method changed

## **10. Future Optimizations**

### **Potential Enhancements**

1. **Sprite Pooling** (if needed):
   - Reuse Sprite objects when tiles change
   - Reduces garbage collection pressure
   - Only needed if tiles update frequently

2. **Texture Atlas** (for even more performance):
   - Combine all 21 textures into single image
   - Single GPU upload for all textures
   - Could improve performance by another 2-3x

3. **Dynamic LOD** (Level of Detail):
   - Use simpler textures when zoomed out
   - Switch to detailed textures when zoomed in
   - Reduces memory and improves performance at large scales

4. **Lazy Texture Generation**:
   - Generate textures on-demand instead of pre-generation
   - Trade startup time for memory efficiency
   - Good for maps with many rare tile types

## **12. Debugging Tips**

### **If Tiles Don't Appear**

1. Check console for texture generation:

   ```
   🎨 Pre-generating tile textures...
   ```

   - If missing: Renderer not accessible

2. Check for sprite render log:

   ```
   🎨 ========== SPRITE RENDER TRIGGERED ==========
   ```

   - If missing: Hook dependencies not triggering

3. Check for errors:

   ```
   ❌ Error rendering tiles: ...
   ```

   - Review stack trace

### **If Tiles Look Different**

1. Verify texture generation uses correct rendering:
   - Check `textureGenerator.ts` calls `renderTile()`
   - Ensure `tileSize` matches (32px)

2. Check variant numbers:
   - Variants should be 0-2
   - Out-of-range variants may render incorrectly

3. Compare colors with `TILE_RENDER_STYLES`:
   - Ensure texture generation uses correct colors

### **If Performance Is Slow**

1. Check texture cache:
   - Call `getTextureCacheStats()` in console
   - Should show 21 textures

2. Verify batching:
   - Open Pixi DevTools (if available)
   - Check draw call count (should be very low)

3. Check sprite count:
   - `tilesLayer.children.length` should equal tile count
   - Too many sprites = memory issue
