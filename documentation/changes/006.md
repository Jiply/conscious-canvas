> "I correctly am unable to pan beyond the map, but I can minimise with two fingers on my trackpad, out of the view of the map. This is incorrect behaviour and should be fixed"

**Symptoms**:

## **2. Solution Implementation**

### **A. Fixed Zoom Constraint (Dynamic Minimum)**

**New Strategy**: Calculate minimum zoom based on viewport size to ensure map always fills the screen.

```typescript
// hooks/use-camera.ts
const getMinScale = useCallback(() => {
  if (!mapSettings || dimensions.width === 0 || dimensions.height === 0) {
    return 0.1;
  }

  const mapWidth = mapSettings.gridWidth * mapSettings.tileSize;
  const mapHeight = mapSettings.gridHeight * mapSettings.tileSize;

  // Calculate scale needed to fit map in viewport
  const scaleX = dimensions.width / mapWidth;
  const scaleY = dimensions.height / mapHeight;

  // Use the LARGER of the two to ensure map is at least as large as viewport in BOTH dimensions
  // This prevents any dimension from being smaller than the viewport (which would cause white space)
  return Math.max(scaleX, scaleY);
}, [mapSettings, dimensions]);
```

**Key Features**:

- ✅ Dynamic minimum based on viewport size
- ✅ Ensures map always fills at least 90% of screen
- ✅ Works with any screen size (desktop, tablet, mobile)
- ✅ Prevents "lost in space" zoom-out experience
- ✅ Applied to both wheel zoom and pinch zoom

**Example Calculations**:

```
Map: 80×50 tiles @ 32px = 2560×1600 px
Viewport: 1920×1080 px

scaleX = 1920 / 2560 = 0.75
scaleY = 1080 / 1600 = 0.675
minScale = max(0.75, 0.675) = 0.75

Result: Can't zoom out beyond 75%
        (map is at least as large as viewport in BOTH dimensions)

At this scale:
  Map width:  2560 * 0.75 = 1920px (= viewport width, no horizontal panning)
  Map height: 1600 * 0.75 = 1200px (> viewport height, user pans vertically)
  ✅ No white space possible!
```

**Zoom Logic**:

```typescript
const handleWheel = (e: WheelEvent) => {
  e.preventDefault();

  const zoomSpeed = 0.001;
  const zoomFactor = 1 - e.deltaY * zoomSpeed;

  setCamera((prev) => {
    const minScale = getMinScale(); // Dynamic minimum!
    const newScale = Math.max(minScale, Math.min(5, prev.scale * zoomFactor));

    // Zoom towards mouse position
    const rect = canvas.getBoundingClientRect();
    const mouseX = e.clientX - rect.left;
    const mouseY = e.clientY - rect.top;

    const worldX = (mouseX - prev.x) / prev.scale;
    const worldY = (mouseY - prev.y) / prev.scale;

    const newX = mouseX - worldX * newScale;
    const newY = mouseY - worldY * newScale;

    return constrainCamera({ x: newX, y: newY, scale: newScale });
  });
};
```

### **`use-map-data.ts` - Convex Queries**

**Responsibility**: Fetch map data from Convex with viewport culling

**Exports**:

```typescript

  places: Place[] | undefined,
  tiles: Tile[] | undefined,

```

**Key Features**:

- ✅ Queries only visible tiles (performance)
- ✅ Calculates viewport region automatically
- ✅ Debounced camera for query stability
- ✅ Padding for smooth scrolling

**Viewport Calculation**:

```typescript
const getVisibleRegion = useCallback(() => {
  if (!mapSettings || !isCameraReady) return null;

  const tileSize = mapSettings.tileSize;
  const padding = 10; // Extra tiles for smooth loading

  // Convert screen coords to world coords
  const viewportLeft = -debouncedCamera.x / debouncedCamera.scale;
  const viewportTop = -debouncedCamera.y / debouncedCamera.scale;
  const viewportRight =
    (dimensions.width - debouncedCamera.x) / debouncedCamera.scale;
  const viewportBottom =
    (dimensions.height - debouncedCamera.y) / debouncedCamera.scale;

  // Convert to tile coords with padding
  const minX = Math.max(0, Math.floor(viewportLeft / tileSize) - padding);
  const minY = Math.max(0, Math.floor(viewportTop / tileSize) - padding);
  const maxX = Math.min(
    mapSettings.gridWidth,
    Math.ceil(viewportRight / tileSize) + padding
  );
  const maxY = Math.min(
    mapSettings.gridHeight,
    Math.ceil(viewportBottom / tileSize) + padding
  );

  return { x: minX, y: minY, width: maxX - minX, height: maxY - minY };
}, [debouncedCamera, dimensions, mapSettings, isCameraReady]);
```

## **7. Technical Details**

### **Hook Dependency Flow**

```
usePixiApp (independent)
    ↓
useMapData (needs dimensions, camera)
    ↓ (provides mapSettings)
useCamera (needs mapSettings, dimensions)
    ↓ (provides camera state)
useTileRenderer (needs tiles, mapSettings, refs)
usePlaceRenderer (needs places, mapSettings, refs)
```

### **Type Safety**

**Challenges**:

- Convex returns `{ _id: Id<"places">, _creationTime: number, ... }`
- Our types expect `{ _id: string, ... }`
- TypeScript strict mode flags this

**Solution**:

```typescript
// Type cast where necessary
places: places as any,  // Accept Convex document types

// Or use proper type guards (future improvement)
```

### **Performance Considerations**

**Camera Debouncing**:

- Live camera: Updates every frame (60 FPS)
- Debounced camera: Updates every 150ms
- Tile queries use debounced camera (reduces query spam)

**Tile Rendering**:

- Batched in 500-tile chunks
- Uses `requestAnimationFrame` between batches
- Prevents main thread blocking
- Total time ~1.3s but non-blocking

**Viewport Culling**:

- Only queries visible tiles + 10-tile padding
- Typical viewport: 60×40 tiles (2400 tiles)
- Full map: 80×50 tiles (4000 tiles)
- Saves 40% of queries on average

## **13. Lessons Learned**

### **When to Refactor**

**✅ Good signs it's time**:

- File > 500 lines
- Multiple concerns mixed
- Hard to add features
- Tests are difficult
- New contributors confused

**❌ Wait if**:

- Feature set unstable
- < 300 lines
- Clear responsibilities
- Easy to understand

### **Refactoring Best Practices**

1. **Extract hooks by concern** (not by feature)
   - Camera state (not "zoom and pan")
   - Data fetching (not "tiles and places")

2. **Keep hooks focused**
   - One clear responsibility
   - 100-200 lines ideal
   - Easy to name (good sign!)

3. **Minimize coupling**
   - Pass only what's needed
   - Avoid prop drilling
   - Use refs for imperative APIs

4. **Test incrementally**
   - Extract one hook at a time
   - Verify behavior unchanged
   - Check linter after each step

### **TypeScript Tips**

1. **Handle Convex types carefully**

   ```typescript
   // Convex returns: { _id: Id<"table">, _creationTime: number, ...data }
   // Your types expect: { _id: string, ...data }
   // Solution: Type cast or extend your types
   ```

2. **RefObject nullability**

   ```typescript
   // Refs can be null initially
   canvasRef: RefObject<HTMLDivElement | null>; // ✅ Correct
   canvasRef: RefObject<HTMLDivElement>; // ❌ Wrong
   ```

3. **Optional chaining in hooks**
   ```typescript
   if (!tilesLayer || !tiles) return; // ✅ Guard clauses
   tilesLayer?.clear(); // ✅ Optional chaining
   ```

## **Post-Release Fix: White Space on Zoom**

### **Issue #1: Initial Report**

After initial deployment, user reported:

> "There's still a bit of white space (beyond the tiles) on the top and left side when I use two fingers to minimise the div."

**Root Cause #1**: Used `Math.max(scaleX, scaleY) * 0.9` which filled only one dimension.

**Attempted Fix #1**: Changed to `Math.min(scaleX, scaleY) * 1.01`

### **Issue #2: White Space with Centering**

User reported again:

> "Now there's still extra space on the left"

**Attempted Fix #2**: Added centering logic when map was smaller than viewport.

### **Issue #3: Don't Center, Prevent Zoom**

User clarified the requirement:

> "Don't center it forcefully, because now there is whitespace on both sides... always disable zooming out the moment doing so would cause white space"

**Root Cause**: The logic was backwards! Using `Math.min` allowed the map to become smaller than the viewport, then trying to "fix" it with centering.

### **Final Solution**

**Use `Math.max` to PREVENT zooming out too far**:

```typescript
// Calculate scale needed to completely fill viewport
const scaleX = dimensions.width / mapWidth;
const scaleY = dimensions.height / mapHeight;

// Use the LARGER of the two to ensure map is at least as large as viewport in BOTH dimensions
// This prevents any dimension from being smaller than the viewport (no white space possible)
return Math.max(scaleX, scaleY);
```

**Simple camera constraints (no centering logic needed)**:

```typescript
// At minimum scale, map is at least as large as viewport in both dimensions
// So we always have panning bounds (no centering, no white space)
const maxX = 0;
const minX = dimensions.width - worldWidth;
const maxY = 0;
const minY = dimensions.height - worldHeight;

return {
  x: Math.max(minX, Math.min(maxX, newCamera.x)),
  y: Math.max(minY, Math.min(maxY, newCamera.y)),
  scale: constrainedScale,
};
```

### **Why This Works**

**The Key Insight**: Don't allow zooming out to a point where white space would appear.

**Example**:

```
Viewport: 1920×1080 px
Map: 2560×1600 px

scaleX = 1920 / 2560 = 0.75 (to fit width)
scaleY = 1080 / 1600 = 0.675 (to fit height)
minScale = max(0.75, 0.675) = 0.75

At 75% zoom:
  Map width:  2560 * 0.75 = 1920px (exactly fits viewport width)
  Map height: 1600 * 0.75 = 1200px (exceeds viewport height)

Result:
  - Width fills perfectly (no horizontal panning needed)
  - Height overflows (user pans vertically to see all content)
  - NO WHITE SPACE POSSIBLE! ✅
```

**User cannot zoom out below 75%** because that would make the map width < 1920px, causing white space.

**Result**: Map is always at least as large as the viewport in both dimensions. User pans to see content, never sees white space! ✅
