### **Implementation Details**

#### **Pixi Application Setup**

```typescript
const app = new Application();
app.init({
  width: 1600,
  height: 900,
  backgroundColor: 0x1a1a1a,
  antialias: false, // Better performance
  resolution: window.devicePixelRatio,
  autoDensity: true,
});
```

**Design Decision**: Disabled antialiasing for better performance with pixel-perfect grid rendering.

#### **Tile Rendering**

**Approach**: Single `Graphics` object for all tiles (batched rendering)

```typescript
const tilesGraphics = new Graphics();

for (const tile of tiles) {
  const visual = TILE_VISUALS[tile.tileType];
  const color = parseInt(visual.color.replace("#", ""), 16);

  // Apply visual variant for diversity
  const variant = tile.visualVariant || 0;
  const finalColor = color - variant * 0x0a0a0a;

  tilesGraphics.rect(x, y, tileSize, tileSize);
  tilesGraphics.fill(finalColor);
  tilesGraphics.stroke({ width: 0.5, color: 0x000000, alpha: 0.2 });
}
```

**Performance**: Single draw call for all tiles (~60 FPS with 4,000 tiles).

#### **Place Labels**

**Text Rendering**: Pixi `Text` objects with custom `TextStyle`

```typescript
const labelStyle = new TextStyle({
  fontFamily: "Arial, sans-serif",
  fontSize: 14,
  fontWeight: "bold",
  fill: 0xffffff,
  stroke: { color: 0x000000, width: 3 },
  dropShadow: {
    alpha: 0.8,
    blur: 2,
    color: 0x000000,
  },
});
```

**Place Filtering**: Only shows main landmarks (excludes `dorm_room`, `common_room`, `study_room`) to reduce visual clutter.

#### **Camera System**

**Implementation**: Container-based transform

```typescript
const worldContainer = new Container();
app.stage.addChild(worldContainer);

// Camera state
const [camera, setCamera] = useState({ x: 0, y: 0, scale: 1 });

// Apply transform
worldContainer.x = camera.x;
worldContainer.y = camera.y;
worldContainer.scale.set(camera.scale);
```

**Pan Controls**:

- Mouse drag to pan
- Tracks `isDraggingRef` and `lastPosRef` for smooth movement

**Zoom Controls**:

- Scroll wheel to zoom (0.1x to 5x range)
- Zoom towards mouse cursor (preserves point under cursor)

```typescript
const zoomFactor = e.deltaY > 0 ? 0.9 : 1.1;
const newScale = clamp(camera.scale * zoomFactor, 0.1, 5);

// Calculate new camera position to zoom towards mouse
const worldX = (mouseX - camera.x) / camera.scale;
const worldY = (mouseY - camera.y) / camera.scale;
const newX = mouseX - worldX * newScale;
const newY = mouseY - worldY * newScale;
```

## **6. Performance Characteristics**

### **Rendering Performance**

- **FPS**: Consistent 60 FPS on modern hardware
- **Memory**: ~50 MB for Pixi app + tile data
- **Draw Calls**: 2-3 per frame (tiles + places + UI)
- **Tile Count**: All 4,000 tiles rendered in single batch

### **Optimization Techniques**

1. **Batched Rendering**: Single `Graphics` object for all tiles
2. **Disabled Antialiasing**: Better performance for grid-based rendering
3. **Container Hierarchy**: Separate containers for tiles and places
4. **Static Tiles**: Tiles are drawn once and cached (not re-drawn per frame)

### **Future Optimizations**

## **9. Known Issues & Limitations**

### **Current Limitations**

1. **No Viewport Culling**: All 4,000 tiles rendered even when zoomed in
   - **Impact**: Slightly reduced performance when zoomed to small region
   - **Mitigation**: Batched rendering keeps FPS at 60

2. **Static Tiles**: No dynamic tile updates (e.g., door animations)
   - **Impact**: Can't visualize door open/close
   - **Future**: Re-render on Convex tile update

3. **No Mobile Touch Controls**: Only mouse input supported
   - **Impact**: Limited mobile experience
   - **Future**: Add touch gestures for pan/zoom

4. **No Minimap**: Hard to navigate when zoomed in
   - **Impact**: Spatial awareness reduced
   - **Future**: Add minimap component

5. **Place Label Overlap**: Labels can overlap at certain zoom levels
   - **Impact**: Reduced readability
   - **Future**: Scale labels with zoom or use LOD

### **Edge Cases**

- **Empty Database**: Shows "Loading map data..." indefinitely if map not seeded
  - **Solution**: User should visit `/init` page first
- **Large Zoom**: Text becomes pixelated at 5x zoom
  - **Expected**: Text is rasterized at 1x scale

## **14. Technical Insights**

### **Why Not @pixi/react?**

**Decision**: Use vanilla Pixi.js with React hooks instead of `@pixi/react`

**Rationale**:

- **Control**: Full control over rendering lifecycle
- **Performance**: Avoid React reconciliation overhead
- **Flexibility**: Direct access to Pixi.js API
- **Simplicity**: Less abstraction layers

**Trade-off**: Manual lifecycle management vs. declarative API.

### **Why Single Graphics Object?**

**Alternative**: Individual `Graphics` per tile (4,000 objects)

**Chosen**: Single `Graphics` with 4,000 draw commands

**Rationale**:

- **Performance**: Fewer scene graph nodes
- **Memory**: Lower overhead per tile
- **Batching**: WebGL can batch draw calls
- **Draw Calls**: 1 vs. 4,000

**Limitation**: Can't individually animate tiles without re-drawing all.

### **Why Container-Based Camera?**

**Alternative**: Manually adjust all object positions

**Chosen**: Transform parent `Container`

**Rationale**:

- **Simplicity**: Single transform affects all children
- **Performance**: GPU handles transform matrix
- **Standard Pattern**: Common in game engines
