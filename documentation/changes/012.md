### **A. Proximity-Based Conversation Bias** ✅

**Issue**: The design document specified that agents should have a bias to talk to each other when in close proximity, but this wasn't reflected in the decision-making code.

**Implementation**: Enhanced LLM decision-making system to detect and prioritize nearby agents

**Changes to `convex/llm.ts`**:

1. **Nearby Agent Detection**:

```typescript
// Get all agents to find nearby ones
const allAgents = await ctx.runQuery(api.agents.listAgents, {});

// Filter for nearby agents (within 2 tiles) who are NOT in active conversations
const TALKING_RANGE = 2;
const nearbyAgents = allAgents
  .filter((other) => {
    if (other._id === args.agentId) return false; // Skip self
    if (other.currentConversationId) return false; // Skip agents already in conversation

    const dx = other.pos.x - agent.pos.x;
    const dy = other.pos.y - agent.pos.y;
    const distance = Math.sqrt(dx * dx + dy * dy);

    return distance <= TALKING_RANGE;
  })
  .map((other) => {
    const dx = other.pos.x - agent.pos.x;
    const dy = other.pos.y - agent.pos.y;
    const distance = Math.sqrt(dx * dx + dy * dy);

    // Get opinion of this agent
    const opinion = agentOpinions.find((op) => op.targetAgentId === other._id);

    return {
      agent: other,
      distance,
      opinion,
    };
  })
  .sort((a, b) => a.distance - b.distance); // Sort by distance, closest first
```

2. **Enhanced Decision Prompt**:

```typescript
// Format nearby agents with opinions and conversation encouragement
let nearbyAgentsSummary = "";
let conversationBias = "";

if (nearbyAgents.length > 0) {
  nearbyAgentsSummary = nearbyAgents
    .map((nearby, idx) => {
      const opinionText = nearby.opinion
        ? ` [You feel: ${nearby.opinion.summary} (sentiment: ${nearby.opinion.sentiment.toFixed(2)})]`
        : " [You haven't formed an opinion about them yet]";

      return `${idx + 1}. ${nearby.agent.name} (${nearby.agent.role}) - ${nearby.distance.toFixed(1)} tiles away${opinionText} [ID: ${nearby.agent._id}]`;
    })
    .join("\n");

  conversationBias = `
⚠️ IMPORTANT - PROXIMITY BIAS:
There ${nearbyAgents.length === 1 ? "is 1 person" : `are ${nearbyAgents.length} people`} VERY CLOSE TO YOU (within 2 tiles)!
As a social being, you should strongly consider engaging in conversation with nearby people, especially if:
- You're not urgently busy with critical needs (hunger > 0.9, sleepiness > 0.9, etc.)
- You have social drive (socialDrive > 0.3) or just want to be social
- They're available and not already in a conversation
- You find them interesting or want to get to know them better

This is a PRIME OPPORTUNITY for social interaction! Don't let it pass by unless you have a very good reason.
Use "EngageConversation" action with their ID to start talking to them.
`;
}
```

3. **Prominent Display in Prompt**:

```typescript
═══════════════════════════════════════════════════════════
NEARBY AGENTS (within 2 tiles - AVAILABLE FOR CONVERSATION):
${nearbyAgentsSummary}

${conversationBias}
═══════════════════════════════════════════════════════════
```

**Impact**: Agents now actively seek out conversations when they detect nearby agents, creating more dynamic social interactions on campus.

## **2. Technical Implementation Details**

### **Data Flow**

```
User clicks agent sprite
  → PixiJS pointerdown event
    → onAgentClick callback with agentId
      → setSelectedAgentId state update
        → setIsConversationSheetOpen(true)
          → ConversationSheet renders
            → Queries:
              - api.agents.getAgent (agent details)
              - api.conversationsMutations.getAgentActiveConversation
              - api.conversationsMutations.getConversationMessages
              - api.agents.getAgent (other participant)
            → Renders agent details + conversation
```

### **Convex Queries Used**

1. **`api.agents.getAgent`**: Fetch agent details
   - Returns: Full agent object with emotions, needs, goals, etc.
   - Called twice: once for current agent, once for conversation partner

2. **`api.conversationsMutations.getAgentActiveConversation`**: Get active conversation
   - Returns: Conversation object with participants, status, turnCount
   - Returns null if agent not in conversation

3. **`api.conversationsMutations.getConversationMessages`**: Fetch conversation history
   - Returns: Array of messages with content, emotion snapshots, timestamps
   - Ordered chronologically

### **Performance Considerations**

- **Lazy Loading**: Sheet only queries data when opened
- **Conditional Queries**: Uses Convex "skip" pattern for optional queries
- **Event Propagation**: Stops propagation to prevent performance issues with map dragging
- **Efficient Rendering**: Only re-renders when selected agent changes

## **9. Known Issues & Limitations**

### **Current Constraints**

1. **Static Profile Pictures**:
   - Profile pictures are hardcoded mappings
   - Not dynamically generated (Gemini integration exists but unused)
   - New agents need manual mapping

2. **Conversation Capacity**:
   - Only supports 2-agent conversations
   - No group conversation support yet
   - Limited to one active conversation per agent

3. **Sheet Size**:
   - Fixed width on larger screens
   - Could be responsive based on conversation length
   - No resize functionality

4. **Performance**:
   - Queries all agents for proximity detection
   - Could use spatial indexing for large agent counts
   - No conversation caching

### **Mitigation Strategies**

- Profile pictures: Use consistent naming convention for easy mapping
- Conversations: Current 2-agent system matches requirements
- Sheet size: 40% width provides good balance
- Performance: Current agent count (8-60) performs well
