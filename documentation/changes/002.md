// Check if agent should go home
const shouldGoHome = (agent) => {
  const currentTime = getSimulationTime();

  const isTired = agent.needs.sleepiness > 0.7;

    path: path,
  });

## **6. Design Decisions**

### **Why Individual Rooms as Place Entities?**

**Alternative Considered**: Store rooms as metadata within main dorm place.

**Chosen Approach**: Each room is a separate `place` document.

**Rationale**:

- **Direct Reference**: Agents can have `homeId` pointing directly to their room
- **Capacity Management**: Each room has independent capacity (2 agents)
- **Query Efficiency**: Can query all agents in a specific room
- **Behavioral Context**: Room-specific events and interactions
- **Future Extensibility**: Room customization, roommate relationships

**Trade-off**: More place documents (19 vs 7), but better semantics and functionality.

### **Why 4×3 Room Size?**

**Rationale**:

- **12 tiles per room**: Sufficient for furniture placement (future)
- **Agent movement**: Enough space for 2 agents without collision
- **Realistic scale**: 4m × 3m ≈ 12 m² (typical dorm room size)
- **Pathfinding**: Adequate walkable interior (6-8 tiles)

### **Why 12 Rooms?**

**Rationale**:

- **Agent capacity**: 24 agents with 2 per room (good for 40-60 agent target)
- **Grid efficiency**: Fits well in 20×13 dorm building
- **Social dynamics**: Enough variety for roommate relationships
- **Computational load**: Manageable number of place entities
